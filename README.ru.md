# @1337exp/pkt-threejs-blueprint

[English](README.md) · **Русский**

Небольшой общий слой, который наши прототипы на Three.js постоянно пишут заново: игровое время с твинами, пружины, которые не разлетаются, случайные числа с зерном и ядро панели «покрутить вживую». Подключай только то, что нужно; лишнего не тянется.

## Стек

TypeScript 6, Vitest, обычный `tsc` (без бандлера: по файлу на модуль и есть tree-shaking). Ядро без зависимостей и без DOM. `three` необязательный peer, он нужен только модулям, у которых это сказано в таблице; `vue` необязательный peer панели. От TaoUI и TaoUX не зависит.

```bash
npm install @1337exp/pkt-threejs-blueprint   # плюс three и vue, если берёшь модули, которым они нужны
```

Работа над самой библиотекой:

```bash
npm install
npm run typecheck
npm test
npm run build
```

## Что умеет

Каждый модуль подключается отдельно (`@1337exp/pkt-threejs-blueprint/<модуль>`), общего входа нет.

| Модуль | Что |
|---|---|
| `ease` | `Ease = (t) => number`, наши кривые (`easeOutBack` с перелётом), `smoothstep(edge0, edge1, x)` в порядке аргументов GLSL |
| `ticker` | `Ticker`: игровое время со `speed` (0 — hit-stop), `tween` и `wait` как обещания, `add`, `busy`, `clear` |
| `spring` | `spring(stiffness, zeta)`, `stepSpring` (число) и `stepSpring3` (вектор): точное решение, устойчиво при любом шаге, один и тот же путь на любой частоте кадров |
| `rng` | `mulberry32(seed)`, `randomInt`; последовательность заморожена тестом, сохранённые зёрна остаются верными |
| `tuning` | `createTuning(values, { groups, storageKey })`: живые значения, сохранение только отличий от умолчаний, сброс, «скопировать как код» (`toSource`), безопасный `localStorage` |
| `loop` | `startLoop(frame, { maxDt })`: цикл кадров; `frame(dt, now)` получает дельту не больше `maxDt` (параметр обязателен: выбираешь ты); `stop()` |
| `renderer` | нужен `three`. `createRenderer(container, parameters, { touchAction })` (холст с `touch-action: none`, пока не передашь `pan-y` и подобное), `bindResize(renderer, container, onResize)`: размер и плотность пикселей с потолком 2, читаются заново при каждом изменении размера |
| `pointer` | нужен `three`. `clientToNdc(event, element)`, `rayOnPlane(ndc, camera, plane)`: от указателя до точки на плоскости, с обновлением матрицы камеры |
| `vue/tuning-panel` | нужен `vue`. `TuningPanel`: рисует `tuning` (группы ползунков, что отличается от умолчаний, «скопировать как код», сброс). Без `.vue`-файла и без UI-библиотеки; вид задают CSS-переменные `--tbp-*`, запасные значения это наша тёмная тема |
| `dispose` | нужен `three`. `disposeObject(root, { textures })`: геометрии и материалы (и массивы) освобождаются один раз, сколько бы мешей их ни делило; текстуры только по просьбе |

```ts
import { Ticker } from '@1337exp/pkt-threejs-blueprint/ticker';
import { easeOutBack } from '@1337exp/pkt-threejs-blueprint/ease';

const ticker = new Ticker();
// каждый кадр: ticker.update(Math.min(realDt, maxDt));
await ticker.tween(0.4, (k) => (mesh.scale.x = 1 + k), easeOutBack);
```

### Дельта кадра

`dt` — время между двумя кадрами в секундах, а не частота симуляции: частота кадров остаётся экранной (60, 120, 144 Гц). Ограничь её сверху (`maxDt`) перед подачей в тикер, чтобы после фона вкладки или подвисания не прилетел `dt` в секунды и все твины не ушли в конец за один кадр. В наших проектах это `1/30`, `0.05` или `0.1`; выбирай осознанно.

Пружине потолок, чтобы выжить, не нужен: `stepSpring` и `stepSpring3` берут точное решение уравнения пружины, поэтому устойчивы при любом `dt` и дают один и тот же путь на 30, 60 и 144 кадрах в секунду. Привычный однострочный шаг Эйлера (`v += (k·(цель − x) − c·v)·dt; x += v·dt`) не даёт ни того ни другого: жёсткость 2000 при `zeta` 1 разлетается ниже ~54 кадров в секунду, а и там, где держится, путь зависит от частоты кадров. Не пиши эту строку руками.

## Как устроено

Три слоя по зависимостям: `core/` (ничего), `three/` (нужен `three`), `components/` (готовые блоки интерфейса поверх ядра; стили это значения нашей тёмной темы, скопированные как CSS-переменные, без TaoUI). Дизайн, решения и анализ, на котором они стоят: [docs/design.md](docs/design.md), [docs/analysis-grok.md](docs/analysis-grok.md).

## Пока нет

Панель на чистом DOM поверх `tuning` (на Vue готова). Частицы, ленты, камеры, bloom и шейдеры остаются в играх намеренно: они разные, потому что разные картинки.
